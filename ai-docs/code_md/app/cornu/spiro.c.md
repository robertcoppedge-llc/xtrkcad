# spiro.c — Spiraletta Curve Rendering (PostScript)

## Overview

`spiro.c` implements the **Spiraletta** algorithm for rendering Bezier curves using **cubic Bézier splines**. The implementation is a postscript emitter that outputs PostScript drawing commands. The core idea: approximate each cubic Bézier curve by splitting it into one or two smaller cubic segments, recursively subdividing until curvature error falls below a threshold.

This module exists primarily for testing and algorithm development — the actual rendering in XTrkCad uses GTK's Cairo backend (via `ctext.c`). However, understanding this code clarifies how Bezier curves are approximated geometrically.

---

## Data Structures

### `spiro_cp` — Control Point with Type

```c
typedef struct {
    double x;      // X coordinate in PostScript user space
    double y;      // Y coordinate (Postscript uses lower-left origin)
    char type;     // 'v' = vertex, 'c' = control point (handle)
} spiro_cp;
```

The `type` field distinguishes between actual path points and Bézier handles. The algorithm builds a list of these pairs to describe the curve piecewise-linearly in PostScript.

### `spiro_seg` — A Single Segmented Curve Piece

```c
typedef struct {
    double ks[4];  // Cubic Bézier coefficients (k0..k3)
} spiro_seg;
```

Each segment represents a portion of the original curve, expressed as a cubic polynomial. The coefficient array `ks` encodes the Bernstein basis expansion:  
`P(t) = k0·B₀(t) + k1·B₁(t) + k2·B₂(t) + k3·B₃(t)` where B_i are the Bernstein polynomials of degree 3.

## Core Functions

### `setup_path(spiro_cp *cp, int n)` — Build a Path from Control Points

Given an array of control points (alternating vertex/handle pairs), this function constructs an internal representation:
1. Creates an array of `spiro_seg` structures, one per segment between consecutive vertices.
2. Computes the cubic Bézier coefficients (`ks[0..3]`) for each segment from its four defining control points.

The resulting segments are stored in a dynamically allocated array; the caller must free it with `free(segs)`.

### `integrate_spiro(const double ks[], double xys[])` — Exact Integral of a Cubic Bézier

Computes the exact integral (area under the curve) of a single cubic segment, returning both X and Y components. This is used internally for geometric properties but not directly exposed in this snippet's output.

### `double dist(double p[2], double q[2])` — Euclidean Distance

Standard helper: computes distance between two 2D points. Used by the curvature error estimator.

### `spiro_seg *print_seg(const double ks[], double x0, double y0,
                        double x1, double y1)` — Subdivision Step

This is the heart of the algorithm. It takes a single cubic segment and decides whether to **split** it or emit it as-is:

#### Decision Criterion

Let `th` be the angle (in PostScript degrees) between the two tangent directions at the endpoints of the segment. Compute:

```
bend = |θ| / 180°   // normalized curvature measure, in [0, 1]
```

If `bend < 1.0`: **Split** — recursively subdivide into two smaller cubic segments (halving each parameter t). The two children are generated by averaging their control points (`(P_i + Q_i)/2` where P and Q are the left/right halves of the original Bezier control polygon).

If `bend >= 1.0`: **Emit** — output a PostScript cubic Bézier command for this segment.

#### Splitting (Recursive Case)

When subdividing:
- The four new control points for each child are computed as midpoints of adjacent edges in the original control polygon plus one extra point on the curve (the de Casteljau intermediate). These form two fresh cubic segments, whose `ks` coefficients are computed and stored in a newly allocated segment.

The recursion depth is unbounded but naturally limited by the error threshold (`bend < 1.`) — straight lines never split further because their bend angle is zero.

#### Emitting (Base Case)

When not splitting, the function prints:
```postscript
x0 y0 moveto
ks[0] ks[1] ks[2] cs
x1 y1 lineto
```

Where `cs` is PostScript's cubic Bézier curve-to operator. The caller wraps each segment with `moveto` (once per path) and a final `stroke`.

## Main Entry Point: `test_curve()`

A standalone test harness that draws a complex closed loop consisting of 12 control-point pairs forming a "flower-like" shape. It repeatedly solves the curve for 1000 iterations to demonstrate robustness (likely testing numerical stability under repeated subdivision). Finally, it emits PostScript with:
- `100 800 translate` — shifts origin to center of drawing area
- `-1 scale` on Y axis (flips because PS has origin at bottom-left)
- The path commands from `print_segs()`

## Summary

| Aspect | Detail |
|--------|--------|
| Output format | PostScript (`.eps`) |
| Algorithm | Recursive subdivision until curvature error < 1° (normalized bend angle) |
| Primitive for output | Cubic Bézier curve (`cs` operator in PS) |
| Recursion base case | Segment is "straight enough" → emit as single cubic segment |
| Subdivision method | De Casteljau midpoint split (averaging control points) |
